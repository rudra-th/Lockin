# Android

The Android surface is a **Capacitor 8 shell around `app/`**, not a second UI.
The web app remains the source of truth for tasks, schedules and sessions; the
shell adds the capabilities a browser cannot have.

> Status: the Capacitor shell builds a debug APK, and the `LockinNative` bridge
> covers exact alarms, full-screen alarm screens, notification permission, usage
> access, per-app screen time, and optional Google sign-in for cloud sync. Device
> testing is the remaining gate before sharing a release APK.
> Lockin distributes directly — no Play Store. The UI still states the web limit
> plainly: the browser build rings only while Lockin is open.

## Build

Prerequisites:

- Android Studio with **JDK 21** (the bundled JBR works).
- Android SDK platform 36 and build-tools 35+.
- Node 22+.

```bash
npm install
npm run android:build         # cap sync android + assembleDebug
```

The helper uses `gradlew.bat` on Windows and `./gradlew` elsewhere. A different
Gradle task passes through: `npm run android:build -- assembleRelease`.

If Gradle cannot find the toolchain:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Launcher and splash
art: `npm run android:icons` (Windows, System.Drawing; no Android Studio).

`android/local.properties` points Gradle at the local SDK and is ignored.
`android/app/src/main/assets/public/` is generated by `cap sync` and is ignored;
run sync after changing anything in `app/`.

## Project shape

```text
android/
  app/src/main/
    AndroidManifest.xml
    java/com/lockin/app/
      MainActivity.java          registers LockinNative
      LockinNativePlugin.java    bridge: alarms, usage, permissions
      AlarmReceiver.java         notification + full-screen intent
      AlarmActivity.java         lock-screen alarm screen
      BootReceiver.java          re-seeds alarms after reboot
      AlarmScheduler.java        shared scheduling/cancel helpers
    res/                         icons, splash, strings
  variables.gradle               SDK levels and AndroidX versions
  capacitor.settings.gradle
```

`capacitor.config.json` sets `webDir: "app"` and `androidScheme: "https"`.
The service worker is not registered inside the native shell; the shell serves
the bundled files directly.

## The bridge contract

`app/assets/js/native.js` is the only web file that talks to `LockinNative`.
Outside the shell every export is inert, so the same `app/` still runs on the
web and in the extension pack.

- On boot it consumes a notification route (cold start lands on Schedule) and
  clears stale alarms — the foreground engine owns the app while it is open.
- On every background transition it seeds the next **14 days** of `remind` and
  `start` events from `eventsBetween`. A `start` event is skipped when the
  block's **Alarm at start** switch is off; the reminder still fires.
- On returning to the foreground it cancels the native window, so an open app
  never rings twice.
- Settings → Android shows live pills for exact alarms, notifications,
  full-screen alarms and usage access, plus a 7-day screen-time panel from
  `UsageStatsManager`.

## Native capabilities

### Exact alarms

- `AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP, at, pendingIntent)`.
- `SCHEDULE_EXACT_ALARM` is declared; on Android 12+ the user may need to grant
  "Alarms & reminders" in system settings. The plugin exposes
  `canScheduleExactAlarms()` and `openExactAlarmSettings()`.
- If permission is denied, fall back to `setAndAllowWhileIdle` and report
  `exact: false` to the web UI. Never claim an exact ring that is not exact.
- A boot receiver re-seeds the next window of alarms from the stored schedule.
- Start alarms ask for a **full-screen intent** on Android 8+ (`AlarmActivity`):
  the screen turns on, the alarm draws over the keyguard, and Dismiss / Open
  Lockin are one tap. Android 14+ can withhold the permission, so the receiver
  checks `NotificationManager.canUseFullScreenIntent()` at runtime. When it is
  denied, the same alarm posts as a loud heads-up notification — never silently.
  Settings → Android shows the current state and opens the system toggle.
- `AlarmActivity` is not exported, does not appear in recents, and owns no
  schedule state: title, body and notification id arrive in the intent.

### Usage access

- `PACKAGE_USAGE_STATS` is a special access permission. The app opens
  `Settings.ACTION_USAGE_ACCESS_SETTINGS`; the user grants it.
- `UsageStatsManager.queryUsageStats` aggregates foreground time per package.
- No history database, no page content, no keylogging.

### Google sign-in (optional sync)

- `@capacitor-firebase/authentication` opens the native Google sheet; the
  returned ID token goes to the Firebase JS SDK (`signInWithCredential`), which
  owns Firestore. `skipNativeAuth: true` keeps a single auth session.
- `android/app/google-services.json` is required for the Firebase integration
  and is **gitignored** — download it from the Firebase console (project
  `lockin-29758`, Android app `com.lockin.app`, release SHA-1 in
  [`android-release.md`](android-release.md)). The web config in
  `app/assets/js/firebase.js` is public by design; Firestore rules are the lock.
- A **debug** APK is signed with the local debug keystore, whose SHA-1 is not
  the release one registered in Firebase — Google sign-in will fail with
  `DEVELOPER_ERROR` until that fingerprint is added to the Firebase Android app
  (and `google-services.json` re-downloaded), or you test an `assembleRelease`
  build signed with the release keystore. The debug fingerprint:
  `keytool -list -v -keystore %USERPROFILE%\.android\debug.keystore -alias androiddebugkey -storepass android`.
- Signing out leaves local data untouched; Settings → **Delete cloud data**
  wipes the Firestore mirror and then signs out.

### Blocking

No blocking tier ships on Android today. Lockin's Android shell measures and
rings; it does not intercept other apps. Site blocking is the **extension's**
job (Chrome, declarativeNetRequest), and the Android screen-time panel is
informational — it shows where time went, it never decides what you can open.

If a blocking tier is ever built, accessibility-based detection is the
mechanism with the worst policy and privacy cost (it can see every foreground
package) — it would be a direct-APK feature with its own consent copy, never
the Play build, and this section would be rewritten to describe exactly what
ships. Until then the docs promise only what the APK does.

## Permissions

Declared in `AndroidManifest.xml` as the features land:

| Permission | Why |
|---|---|
| `INTERNET` | Capacitor local server and future opt-in sync |
| `SCHEDULE_EXACT_ALARM` | Ring at the scheduled minute |
| `POST_NOTIFICATIONS` | Alarm and reminder notifications |
| `USE_FULL_SCREEN_INTENT` | Show a start alarm over the lock screen (Android 14+ runtime gate; falls back to heads-up) |
| `RECEIVE_BOOT_COMPLETED` | Re-seed alarms after a reboot |
| `VIBRATE` | Alarm pattern |
| `WAKE_LOCK` | Deliver the alarm receiver on time |
| `PACKAGE_USAGE_STATS` | Per-app screen time (special access) |

## Release signing

The release signing setup lives in [`android-release.md`](android-release.md):
a gitignored `android/keystore.properties` feeds `signingConfigs.release`, and
`assembleRelease` fails fast — naming the missing piece — until the keystore
exists. Debug builds never touch signing.

## Play policy notes

- Accessibility-based app blocking is high risk for Play; Lockin ships no
  blocking tier on Android (see "Blocking" above).
- `QUERY_ALL_PACKAGES` is restricted; avoid it unless the core feature requires
  it and the declaration is approved.
- Full-screen intents are restricted on Android 14+; the app checks the
  permission at runtime, offers the system toggle in Settings, and degrades to
  a heads-up notification.
- Exact alarms require a user-facing rationale and the `SCHEDULE_EXACT_ALARM`
  permission; the app must degrade gracefully when denied.
- A privacy policy and Data Safety declaration are mandatory before any store
  listing. Draft from [`privacy.md`](privacy.md) and
  [`permissions.md`](permissions.md).
